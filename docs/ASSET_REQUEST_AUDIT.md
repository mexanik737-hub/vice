# Как игра запрашивает изображения, видео и аудио

Дата проверки: 26 ноября 2026 года.

## Схема запросов в исходной игре

- Изображения задаются как `Media/...` и выводятся через обычные `<img src>`, SugarCube-ссылки `@src`, а также через макросы `DrawImage` и `DrawImg`. Встречаются изображения персонажей, предметов, событий, карточек NPC и фонов.
- Фоны передаются в виджет `SetBackground`, который вызывает `updateBackground(...)`; это CSS-изображение с относительным путём `Media/...`.
- Видео выводятся виджетом `Video` в HTML5 `<video>` с `controls`, `autoplay`, `loop`, `muted`, `playsinline` и `preload="metadata"`. Перед привязкой `src` виджет приводит обратные косые черты к `/`.
- Фоновый дождь использует HTML Audio API (`new Audio(path)`) с путями `Media/Audio/Weather/*.wav`. Запросы аудио также являются локальными файловыми запросами WebView.
- В исходном HTML обнаружено 350 упоминаний `.mp4`, 26 `.webm`, 733 `.jpg`, 30 `.jpeg`, 174 `.png`, 5 `.webp` и 8 `.wav`. Это число вхождений расширений, а не число отдельных файлов; часть путей собирается динамически.

## Как их обслуживает Android

- HTML открывается как `file:///android_asset/game/index.html`, без сервера.
- WebView отправляет запросы к относительным `Media/...` как локальные file URL. `shouldInterceptRequest` ищет сегмент `/Media/` в пути URI, переводит `\\` в `/`, проверяет сегменты на `.` и `..`, затем находит файл под SAF-корнем, который выбрал пользователь.
- Файлы читаются напрямую через `ContentResolver`; приложению не требуется копировать Media во внутреннее хранилище.
- Для видео обрабатывается `Range: bytes=...` и возвращается ответ `206 Partial Content` с `Content-Range`, что нужно для метаданных и перемотки. Изображения и аудио отдаются обычным ответом `200`.
- Уточнено определение MIME: если SAF-провайдер возвращает `application/octet-stream`, тип берётся по расширению. Это помогает WebView с видео, изображениями и аудио у провайдеров, которые не сообщают тип содержимого.
- Пользователь должен выбрать именно корневую папку `Media`, содержащую каталоги `Characters`, `Locations`, `Sex`, `Audio` и другие. Без выбора внешних ресурсов HTML по этим путям не найдёт.

## Ограничения проверки

- В проекте нет исходной папки с ресурсами игры; есть только синтетические тестовые JPEG, WebM и WAV. Наличие оригинальных файлов и точное совпадение регистра/названий не проверены.
- Код Android статически проверен, но не собран. SAF, диапазонные ответы и воспроизведение на Samsung Android 17 не проверялись на устройстве.
- На Android-провайдере с нестандартными URI или ошибочной поддержкой `AssetFileDescriptor` возможны отличия; требуется проверка реального дерева Media на телефоне.


## Результат статической проверки

- Виджет `Video` создаёт HTML5 video-узел и заменяет обратные слеши в динамическом пути на обычные разделители каталогов.
- `DrawImage` задаёт `src` у изображения; персонажи и карточки также строят `src` через обычные DOM-узлы. `SetBackground` вызывает игровую функцию установки фона с тем же относительным Media-путём.
- Дождевой звук загружается через `new Audio(path)`. Android-клиент перехватывает запросы ресурсов независимо от того, создаёт их HTML video/img, CSS фон или Audio API.
- Добавлена MIME-подстраховка для SAF-провайдеров, возвращающих общий `application/octet-stream`; статический тест проверяет её наличие, но MIME-поведение реального провайдера на телефоне не измерено.
